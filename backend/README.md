# Production-Grade AI Chatbot Platform Backend

A production-quality standalone conversational AI chatbot platform backend developed in Java 21 LTS with Spring Boot 3.4.

---

## 1. Streaming Architecture (Phase 7)

Phase 7 introduces progressive, real-time AI response streaming powered by Server-Sent Events (SSE) and Java 21 Virtual Threads. Chunks generated by the underlying AI Provider (Ollama or future adapters) are delivered incrementally to client frontends with minimal latency while safeguarding database connection pools and strict message ordering.

```text
Frontend
   |
   | POST /api/v1/conversations/{id}/messages/stream
   v
Spring Security (JWT Filter & Principal Resolution)
   |
   v
Streaming Controller (MessageController)
   |
   v
ChatService
   |
   +---- Transaction 1: Validate Message Size & Persist USER Message (Pessimistic Lock, Commit)
   |
   +---- Context Assembly: Bounded History Fetch & ConversationContextBuilder
   |
   v
AiProvider Abstraction (Provider-Neutral stream contract)
   |
   v
OllamaAiProvider (Native NDJSON Line-by-Line Stream Consumption)
   |
   | Chunk Event (real-time delta)
   v
SseEmitter (Java 21 Virtual Thread async dispatch)
   |
   v
Frontend Client (Progressive markdown rendering)
   |
   | Stream Completion
   v
ChatService
   |
   +---- Transaction 2: Persist ASSISTANT Message (SENT) & Record AiAuditLog
   |
   v
SSE Event: message_complete
```

## 2. Server-Sent Events (SSE) Endpoint

### HTTP Request
```http
POST /api/v1/conversations/{conversationId}/messages/stream HTTP/1.1
Host: localhost:8080
Authorization: Bearer <JWT_TOKEN>
Content-Type: application/json
Accept: text/event-stream

{
  "content": "Patient reports severe chest pain and elevated troponin levels. Provide clinical triage steps.",
  "metadata": {
    "urgency": "STAT",
    "department": "Cardiology"
  }
}
```

### Security & Guards
- **Authentication**: JWT token required in `Authorization` header. Unauthenticated requests receive `401 Unauthorized`.
- **Ownership**: The authenticated user must own the conversation (`user_id` matches JWT principal). Mismatched requests receive `403 Forbidden`.
- **Status Validation**: Conversations marked as `DELETED` return `400 Bad Request`.
- **Oversized Message Guard**: If the current user message exceeds the context input budget (`maxTokens - reservedOutputTokens`), it is rejected immediately with `400 Bad Request` prior to database persistence or AI invocation.

## 3. SSE Event Contract

The SSE endpoint emits five distinct application-level events. No provider-specific JSON or internal stack traces are ever exposed to the client.

| Event Type | Event Name | Description |
|---|---|---|
| `MESSAGE_START` | `message_start` | Signals that generation has begun and provides the conversation ID and assistant role. |
| `CONTENT` | `content` | Emits incremental token/text delta with 1-based sequence numbering. |
| `HEARTBEAT` | `heartbeat` | Emitted periodically (configurable, default 15s) to prevent intermediate proxies/firewalls from dropping idle connections. |
| `MESSAGE_COMPLETE` | `message_complete` | Final event containing saved message ID, latency metrics, token consumption, and finish reason. |
| `ERROR` | `error` | Emitted upon provider or system failure with sanitized error code and message. |

## 5. Persistence Lifecycle & Concurrency Invariants

To avoid exhausting database connection pools during potentially long LLM generations (10–60 seconds), `ChatService` uses a **Split-Transaction Lifecycle**:

```text
Transaction 1 (User Message Persistence)
    |
    +-- Lock Conversation row (findByIdForUpdate)
    +-- Allocate sequenceNumber deterministically
    +-- Save USER Message (status: SENT)
    +-- Update Conversation.updatedAt
    +-- COMMIT & RELEASE DB CONNECTION
         |
         v
Non-Transactional Streaming (Java 21 Virtual Thread)
    |
    +-- Stream chunks over SSE (zero DB locks / connections held)
    +-- Accumulate full content internally
         |
         v
Transaction 2 (Assistant Message Persistence)
    |
    +-- Lock Conversation row (findByIdForUpdate)
    +-- Allocate next sequenceNumber deterministically
    +-- Save ASSISTANT Message (status: SENT)
    +-- Save AiAuditLog entry
    +-- COMMIT & RELEASE DB CONNECTION
```

## 6. Failure & Cancellation Behavior

1. **Provider Failure Before Any Content**:
   - USER message remains committed and persisted.
   - NO fake ASSISTANT message is persisted.
   - Sanitized `StreamErrorEvent` is emitted over SSE.
   - Failure logged in `AiAuditLog` with `finishReason: ERROR`.
   - Resources cleaned up; `SseEmitter` completed.
2. **Provider Failure After Partial Content**:
   - Invariant: `partial generation != successful assistant response`.
   - Incomplete assistant message is persisted with `MessageStatus.FAILED` and metadata `partialStream: true`.
   - Sanitized `StreamErrorEvent` is emitted over SSE.
   - Failure logged in `AiAuditLog`.
3. **Client Disconnect / Timeout**:
   - When the client browser terminates or connection times out, `emitter.onError`, `emitter.onTimeout`, or an `IOException` triggers cancellation.
   - `AiStreamHandle.cancel()` aborts the underlying HTTP response stream.
   - Heartbeat scheduler is immediately shut down.
   - If partial content was emitted, persisted as `MessageStatus.FAILED` with `finishReason: CANCELLED`.
   - Audit log recorded as `CANCELLED`.

## 7. Provider Streaming Abstraction

The `AiProvider` interface supports both synchronous generation and asynchronous streaming:

```java
public interface AiProvider {
    ProviderType getProviderType();
    AiResponse generate(AiRequest request);
    boolean isAvailable();

    default AiStreamHandle stream(AiRequest request, AiStreamListener listener) {
        // Fallback for providers without native streaming
        AiResponse response = generate(request);
        listener.onStart();
        listener.onChunk(new AiStreamChunk(response.content(), response.model(), 1, true));
        listener.onComplete(response);
        return new AiStreamHandle() {
            @Override public void cancel() {}
            @Override public boolean isCancelled() { return false; }
        };
    }
}
```

`OllamaAiProvider` implements native streaming by sending `stream: true` to Ollama's `/api/chat` and reading NDJSON lines as they arrive via `BufferedReader` without memory buffering.

## 8. Configuration

Streaming configuration is externalized in `application.yml` under `ai.streaming.*`:

```yaml
ai:
  default-provider: OLLAMA
  default-model: llama3.2:3b
  streaming:
    enabled: ${AI_STREAMING_ENABLED:true}
    timeout-ms: ${AI_STREAMING_TIMEOUT_MS:120000}
    heartbeat-enabled: ${AI_STREAMING_HEARTBEAT_ENABLED:true}
    heartbeat-interval-ms: ${AI_STREAMING_HEARTBEAT_INTERVAL_MS:15000}
  context:
    max-messages: 20
    max-tokens: 4096
    reserved-output-tokens: 1024
  ollama:
    base-url: ${AI_OLLAMA_BASE_URL:http://localhost:11434}
    connect-timeout-ms: 5000
    read-timeout-ms: 60000
```

## 9. Automated Testing Strategy

Automated tests run completely offline with zero external network dependencies or real Ollama requirements:
- **`StreamingEventModelTest`**: Validates SSE records and event immutability.
- **`OllamaAiProviderStreamingTest`**: Tests HTTP NDJSON line streaming, chunk emission, cancellation handles, and error mapping using Spring's `MockRestServiceServer`.
- **`ChatServiceStreamingTest`**: Validates split-transaction boundaries, USER persistence, partial failure handling (`FAILED` status), oversized message rejection, and audit logging.
- **`MessageStreamingIntegrationTest`**: Tests end-to-end `POST /messages/stream` SSE endpoints with MockMvc, JWT auth, ownership enforcement, and headers.
- **`StreamingCancellationTest`**: Tests disconnect and timeout event handling.
